# دليل تطبيق التصميم الجديد (HeroUI v3) على باور كولكت

هذا الدليل هو المرجع الوحيد لتطبيق التصميم الذي اعتُمد في النموذج الأولي (`powercollect-heroui-prototype.html`) على الموقع الحقيقي (Laravel 13 + Inertia v3 + React 19، عربي من اليمين لليسار). كل قيمة هنا مأخوذة من ملفات النموذج نفسها (`prototype-source.zip`)، وكل قرار مأخوذ مما اتُّفق عليه في جلسة التصميم.

> **قبل البدء بأي كود:** التنفيذ لا يبدأ إلا بعد أن يقول صاحب المشروع «ابدأ بالكود». هذا الدليل يصف ما سيُبنى وكيف، ولا يغني عن تلك الموافقة.

## 1. النطاق والقواعد الثابتة

1. **لا زيادة ولا نقصان:** كل صفحة ونافذة وزر وحقل موجود في الموقع يبقى كما هو بأسمائه وترتيبه وقواعد التحقق فيه. يتغيّر الشكل فقط. لا تُضاف حقول ولا تُحذف، ولا يتغيّر سلوك الخادم.
2. **«تصحيح دفعة» خارج النطاق:** لا يُعاد تصميمه. يبقى بشكله وسلوكه الحاليين.
3. **التصميم مترابط:** المكوّن نفسه يُستعمل للغرض نفسه في كل مكان. مثلًا اللون الذي يعني «دفعة» يعني دفعة في الزر والشارة وصف الجدول.
4. **البيانات الكثيرة تُعرض بهدوء:** الجداول الكثيفة تعرض الأعمدة الأساسية فقط، والتفاصيل عند الطلب (انظر §11).
5. **ممنوع اللون البرتقالي المملوء على الأزرار.** البرتقالي للاختيار والتركيز والهوية فقط (انظر §3).
6. **العربية أولًا:** الاتجاه من اليمين لليسار في كل شيء. تُستعمل الخصائص المنطقية (`inset-inline-start`، `ms-*`/`me-*`، `ps-*`/`pe-*`، `text-start`/`text-end`) ولا تُستعمل `left`/`right`.
7. **اتباع قواعد المشروع:**
   - `CLAUDE.md`
   - `.ai/rules/*.md`، خاصة `js.md` و`controllers.md` و`models.md`
   - مهارة `inertia-react-development` لكل عمل في React/Inertia
   - `vendor/bin/pint --dirty --format agent` بعد أي تعديل PHP
   - تحديث الاختبارات عند تغيّر السلوك

## 2. الأساس التقني

### 2.1 ما أُنجز

- **Tailwind CSS 4.3.5** مثبّت (commit `12c36dd` على الفرع `claude/modest-galileo-i28caq`)، والموقع مطابق لشكله على Tailwind 3. التحقق شمل:
  - تنسيق كل عنصر في 39 صفحة، بالوضع العادي والهافر والتركيز، بالثيمين.
  - لقطات كاملة لـ 25 صفحة.
- **ترتيب الأنماط في `resources/css/app.css` (مهم لما بعده):**
  - متغيرات الثيم و`components.css` وأدوات Tailwind وقواعد `app.css` كلها بلا طبقة (unlayered)، بهذا الترتيب، كما كانت في Tailwind 3.
  - في طبقة `base` فقط: الـ preflight، والإضافة `@tailwindcss/forms`، وقواعد الحقول.
- **خط Zain** موجود في `resources/fonts/` و`resources/css/fonts.css` بالأوزان 300 و400 و700 و800 و900.
- **شعار الشركة (MA)** موجود في `public/images/logo-ma.svg`. الجزء M لونه `#2A2D34`، والجزء A لونه `#E2642A`.
- **React 19** موجود.

### 2.2 التثبيت (يحتاج موافقة صاحب المشروع لأنه تغيير في الاعتماديات)

```bash
npm install @heroui/react@^3 @heroui/styles@^3
```

جُرّب في الجلسة الإصدار `@heroui/styles` 3.2.7. ثبّت أحدث 3.x، وتأكد من رقمه بالأمر `npm ls @heroui/react @heroui/styles`، واقرأ توثيقه في https://heroui.com/en/docs/react/components قبل كتابة الكود.

**لا تكتب `@import "@heroui/styles"` كاملًا.** هذا الاستيراد يجلب `tailwindcss` من جديد بطبقاته، فيكسر الترتيب المسطّح في §2.1. استورد الأجزاء يدويًا، كما في قسم «Importing Specific Components» في README الحزمة:

```css
/* resources/css/app.css: أعلى الملف، بعد سطر @layer الحالي وقبل استيراد أدوات Tailwind */
@import '@heroui/styles/utilities';
@import '@heroui/styles/variants';
@import '@heroui/styles/themes/default' layer(theme);
@import '@heroui/styles/components/index.css' layer(components); /* أو ملفات المكونات المستعملة فقط: components/button.css … */
@import './heroui-theme.css';                           /* ألوان (ج): الملف في §3.1، بلا طبقة حتى يغلب الافتراضي */
```

بعد إضافة هذه الأسطر:

1. شغّل `npm run build`.
2. تحقق من أن أنماط HeroUI جاءت في طبقة `components`، وأن أدوات Tailwind ما زالت بلا طبقة.
3. أعد فحص المطابقة (§15.2) على صفحة واحدة على الأقل قبل المتابعة.

**تعارضات يجب معالجتها:**

| التعارض | المعالجة |
| --- | --- |
| HeroUI يحدد `--radius` و`--spacing` و`--background` و`--foreground` و`--border` | قبل التثبيت، ابحث بـ `grep -rn -- "--radius\|--spacing\|--background\|--border" resources/css` عن الأسماء التي يستعملها الموقع لمعانٍ أخرى. أي اسم متعارض يُعاد تسميته في الموقع، لا في HeroUI. |
| الثيم الداكن: HeroUI يقرأ `.dark` و`[data-theme="dark"]`، والموقع يستعمل الصنف `.dark` (`@custom-variant dark`) | متوافقان. لا تغيّر شيئًا. |
| `@tailwindcss/forms` يرسم الحقول العادية | الحقول التي تصبح مكونات HeroUI لا تحتاجه. أبقِه حتى ينتقل آخر حقل، ثم احذفه في مرحلة أخيرة، بموافقة. |

### 3.2 أين يظهر البرتقالي (وأين لا)

**يظهر في:**
- الحقل المختار أو المركّز عليه: حلقة 2px.
- البطاقة المختارة في مجموعات الاختيار: حلقة 2px، وخارجها هالة 5px بـ `--accent-soft`.
- مربع الاختيار المحدد.
- التبويب الفعّال: عدّاده بخلفية `accent-soft`.
- شارات الفلاتر المفعّلة.
- مؤشر الصفحة الحالية في الشريط الجانبي: خط 3px بلون الشعار `#E2642A`.
- منحنى التحصيل في الرئيسية: العنصر «البطل» الوحيد.
- الشعار والإيصال وبطاقة المشترك.

**لا يظهر في:**
- خلفية أي زر.
- أي حالة (الإنذار عنبري، والخطأ قرمزي).
- الأرقام والأشرطة (لونها فحمي `--data`).

### 3.3 ألوان الحركات المالية (هادئة، لكل فعل لونه)

كل نوع حركة له لون واحد، يُستعمل بالطريقة نفسها في الزر والشارة وأيقونة الجدول وعنصر القائمة. الاستعمال: `data-tone="pay"` وأمثاله، أو `variant` مخصّص على مكوّن HeroUI.

| الحركة | `--t-*` | `--t-*-solid` (زر مملوء) | `--t-*-ink` فاتح / داكن |
| --- | --- | --- | --- |
| تسجيل دفعة (`pay`) | `oklch(0.6 0.14 152)` | `oklch(0.5 0.12 152)` / داكن `0.52` | `oklch(0.42 0.1 152)` / `oklch(0.82 0.12 152)` |
| تحميل حركة (`charge`) | `oklch(0.6 0.17 12)` | `oklch(0.52 0.17 14)` / `0.54` | `oklch(0.45 0.15 14)` / `oklch(0.8 0.12 14)` |
| خصم (`discount`) | `oklch(0.58 0.16 300)` | `oklch(0.5 0.16 300)` / `0.52` | `oklch(0.44 0.14 300)` / `oklch(0.8 0.11 300)` |
| مقاصة (`clearing`) | `oklch(0.6 0.09 205)` | `oklch(0.5 0.08 210)` / `0.52` | `oklch(0.42 0.07 210)` / `oklch(0.82 0.08 205)` |
| دفعة مقسّمة (`split`) | `oklch(0.56 0.13 262)` | `oklch(0.48 0.13 262)` / `0.5` | `oklch(0.42 0.12 262)` / `oklch(0.8 0.1 262)` |
| قراءة (`reading`) | `oklch(0.55 0.02 265)` | `oklch(0.42 0.015 265)` / `0.45` | `oklch(0.38 0.015 265)` / `oklch(0.82 0.012 265)` |

**كيف يُرسم الزر:**
- **الزر الخفيف (الافتراضي لأفعال المال):**
  - الخلفية: `color-mix(in oklab, var(--tone) 13%, var(--surface))`، وتصبح 21% عند الهافر.
  - النص: `--tone-ink`.
- **الزر المملوء:**
  - الخلفية: `--tone-solid`، والنص أبيض.
  - الهافر: `color-mix(in oklab, var(--tone-solid) 86%, black)`.
  - **زر مملوء واحد فقط في كل صفحة**، وهو الفعل الأهم فيها. مثلًا «تسجيل دفعة» في كشف الحساب يكون أخضر مملوءًا.

**الشارات:**
- الخلفية: `color-mix(in oklab, var(--tone) 14%, transparent)`، والنص: `--tone-ink`.
- الشارة التي تقع مباشرة على الصفحة (لا داخل بطاقة) تُمزج مع `--surface` بدل `transparent`، حتى لا يضعف تباينها في الشكل الزجاجي.

### 3.4 التباين

كل نص يجب أن يحقق WCAG AA على الشكلين المصمت والزجاجي، فاتحًا وداكنًا. هذا هو سبب وجود طبقة `-ink`: لا تكتب نصًا بلون الحالة الأصلي (`--success` مثلًا) على خلفية فاتحة. استعمل `--success-ink`.

## 4. الخطوط

- **Zain** لكل شيء: النصوص، العناوين، الأرقام، الجداول، القوائم. الأوزان 300 و400 و700 و800 و900. هو محمّل في المشروع، فلا تستعمل Google Fonts وقت التشغيل.

- لا `letter-spacing` على العربية.
- **السلّم المستعمل في النموذج:**

## 5. الشعار والهوية

**الشعار في الشريط الجانبي:**
- هو أكبر شيء في الشريط الجانبي.
- في أعلى الصفحة (قبل أي تمرير):
  - الشريط الضيق: الشعار بعرض 60px، وارتفاع منطقته 104px.
  - الشريط الموسّع: الشعار بعرض 84px، بمحاذاة البداية.
- عند التمرير لأسفل:
  - يصغر الشعار إلى 44px، وترتفع منطقته إلى أعلى الشاشة بارتفاع 68px.
  - يصبح الشعار **في منتصف الشريط الجانبي**، ويظهر تحته خط فاصل.
- الحركة: `.32s cubic-bezier(.2,.8,.2,1)`، وتُلغى مع `prefers-reduced-motion`.

**اسم الشركة في الشريط العلوي:**
- لا يظهر في أعلى الصفحة.
- يظهر عند التمرير، بانزلاق إلى جانب الشعار: الاسم بخط Alexandria 800 حجم 17px، وتحته سطر النشاط بخط Zain 700 حجم 13.5px بلون `--brand-ink`.
- على الجوال (أقل من 900px): الشعار بعرض 34px في الشريط العلوي، ويظهر الاسم بعد التمرير.

**ألوان الشعار:**
- M بلون `--mark-ink`: `#2A2D34` في الفاتح، و`--foreground` في الداكن.
- A بلون `#E2642A` دائمًا.

**الهوية تظهر في أماكن مختارة فقط:**
- **الإيصالات:** خط علوي بلون `#E2642A` سمكه 3px، والشعار بعرض 46px، واسم الشركة بخط Alexandria.
- **بطاقة المشترك:** تدرّج فحمي مع وهج برتقالي، والشعار أبيض.
- **مؤشر الصفحة الحالية** في الشريط الجانبي.
- **صورة المستخدم الافتراضية:** تدرّج برتقالي هادئ إلى فحمي.

## 6. الأسطح: مصمت وزجاجي، والقوائم العائمة

**شكلان للواجهة:** مصمت (الافتراضي) وزجاجي. يُضافان كخيار في صفحة «الهوية والمظهر» الموجودة، مع الحفاظ على كل حقولها الحالية.

**الشكل الزجاجي:**

| العنصر | الخلفية |
| --- | --- |
| البطاقات | `color-mix(in oklab, var(--surface) 72%, transparent)` في الفاتح، و58% في الداكن، مع `backdrop-filter: blur(22px)` |
| النوافذ | `surface` بنسبة 78%، مع `blur(28px) saturate(1.5)` |
| خلفية الصفحة | توهّج برتقالي خفيف من الأعلى (16%) وتوهّج فحمي من الأسفل (10%) |

**القوائم والنوافذ العائمة زجاجية مضبّبة دائمًا، في الشكلين.** يشمل ذلك القوائم المنسدلة (Dropdown/Menu)، والقوائم القصيرة (Select/ListBox)، والتقويم، وقائمة إجراءات الصف في كشف الحساب. الهدف أن تبدو طافية فوق الصفحة، فيميّز المستخدم ما يضغطه:

```css
background: color-mix(in oklab, var(--surface) 74%, transparent);   /* داكن: 70% */
backdrop-filter: blur(22px) saturate(1.7);
box-shadow: 0 0 0 1px color-mix(in oklab, var(--foreground) 10%, transparent),
            0 24px 48px -12px rgb(0 0 0 / .35), 0 8px 16px -8px rgb(0 0 0 / .2);
/* داكن: 0 0 0 1px rgb(255 255 255 / .1), 0 24px 56px -12px rgb(0 0 0 / .7) */
max-height: calc(100dvh - 24px); overflow-y: auto;
```

**قواعد مكملة للقوائم:**
- مع `prefers-reduced-transparency: reduce` تصبح القائمة مصمتة (`--surface`) بلا ضبابية.
- القائمة لا تخرج من الشاشة: تُضبط إزاحتها لتبقى داخلها.
- القائمة التي في عناصرها سطر شرح تكون بعرض 300 إلى 340px.

**الوضع الداكن، قاعدة صارمة:** لا يظهر أي مربع أو شريط أبيض في الداكن، لا في الإيصال ولا في الأزرار ولا في الأقسام. كل سطح أبيض في الفاتح يقابله `--surface` أو `--surface-secondary` في الداكن. والظلال في الداكن تُستبدل بحدّ داخلي خفيف.

## 7. حالات التفاعل (هافر، ضغط، تركيز)

| العنصر | الهافر | الاختيار / التركيز |
| --- | --- | --- |
| الحقول والبطاقات القابلة للاختيار | حلقة 1px: `color-mix(foreground 18%)` (داكن 22%) | حلقة 2px بـ `--accent`، والخطأ حلقة 2px بـ `--danger` |
| بطاقة مختارة (طريقة الدفع، البنك، النوع) | تبقى الحلقة البرتقالية | 2px `--accent` وهالة 5px `--accent-soft` |

### 10.4 نافذة إضافة المشترك وتعديله

- **نموذج واحد يُمرَّر، لا خطوات بزر «التالي».** المراحل الأربع الحالية تصبح أقسامًا في الصفحة نفسها، مع فهرس جانبي:
  1. البيانات الشخصية
  2. العداد والقاطع
  3. العنوان
  4. بيانات الدفع والاشتراك
- **الفهرس الجانبي** يعمل كـ scroll-spy:
  - لكل قسم: أيقونة، واسم، وسطر وصف، ودائرة الحالة (خضراء عند الاكتمال، حمراء عند وجود خطأ).
  - القسم الحالي: خلفية `surface` وظل.
  - على الجوال يصبح الفهرس شريطًا أفقيًا أعلى النموذج.
- **الحقول الإضافية** (التي كانت تظهر بزر «+»): **ظاهرة افتراضيًا**، ويمكن للمستخدم إخفاؤها فقط. لا تُخفى خلف زر إضافة.
- **بيانات الدفع** (الحد الأدنى وما يتعلق به) **تبقى ظاهرة دائمًا** ولا تُطوى.
- **اختيار الطبلون:**
  - قائمة منسدلة مع بحث (ComboBox)، وخياراتها **بطاقات**.
  - البطاقة ارتفاعها 64px، وفيها أيقونة 36px، والاسم، وسطر تفاصيل (المكان، الامتلاء).
  - البطاقة المختارة: حلقة برتقالية 2px.
  - البحث يعمل بالاسم والرقم والمنطقة.
- **الذيل:** شريط التقدم (عدد الأقسام المكتملة) والأزرار، ويبقى ثابتًا أسفل النافذة.

| رقم الحساب | رمادي، وزن 600 |

| التقدم | شريط ونسبة، وعرضه الأدنى 140px |
| نعم/لا | أيقونة: خضراء للنعم، ورمادية باهتة للا |
| الإجراءات | زر ⋮ بمقاس 34px يفتح قائمة زجاجية. عناصر القائمة بأيقوناتها ولون حركتها، والخطر في آخرها بعد فاصل |

**صف المجموع:** وزن 800، وخلفيته `surface-secondary`.

### 11.5 الجداول الكثيفة: التفاصيل عند الطلب

- **7 أعمدة كحد أقصى ظاهرة.** ما زاد ينتقل إلى «تفاصيل الصف».
- يُفتح بزر سهم في بداية الصف بمقاس 28px، يدور 180° عند الفتح.
- التفاصيل تظهر تحت الصف في بطاقة:
  - شبكة أعمدتها `minmax(170px, 1fr)`.
  - التسمية 11.5px رمادية، والقيمة 13.5px بوزن 600.
- يُطبَّق على المشتركين والسجل المالي والصناديق وكشف الحساب، وعلى كل جدول فيه أكثر من 7 أعمدة.

### 11.6 الذيل والحالات

- **الذيل:**
  - العدد: «عرض 1 إلى 25 من 2,460».
  - عدد الصفوف في الصفحة.
  - الترقيم: أزرار 34px، والصفحة الحالية بخلفية `foreground`.
- **الحالة الفارغة:** أيقونة 56px، وعنوان، وجملة توجيه، وزر الفعل المناسب.
- **التحميل:** هيكل متلألئ (shimmer) بدل محتوى الخلايا.

### 11.7 الجوال

- كل صف يصبح بطاقة بزوايا 16px وخلفية `surface-secondary`.
- كل خلية سطر: التسمية رمادية والقيمة بجانبها.
- مربع التحديد وزر الإجراءات في زاوية البطاقة.
- **مؤشرات أعلى صفحات القوائم (KPI):** بطاقات عرضها الأدنى 200px. التسمية 13px، والرقم 26px بوزن 800، وتحته ملاحظة.

## 12. كشف حساب المشترك (تصميم خاص)

**الرأس:**
- رابط الرجوع.
- اسم الحساب كتمهيد، ثم الاسم بحجم 40px.
- الحالة: شارات الحالة، وشارة الدين الحمراء القابلة للضغط.
- أدوات الكشف عند النهاية.

**شريط الأفعال:**
- حبة بزوايا 20px، زجاجية في الشكل الزجاجي.
- فيه كل أفعال الكشف بألوان حركاتها:
  - تسجيل دفعة: مملوء أخضر
  - تحميل
  - خصم
  - مقاصة
  - دفعة مقسّمة
- تسمية «الإجراءات» في بدايته، وتختفي على الجوال.

**المؤشرات:**
- خمس بطاقات: الرصيد أعرض من البقية (1.3).
- الرصيد المدين: خلفية `danger` 9% ورقم `--danger-ink` بحجم 32px.
- الرصيد الدائن: خلفية `success` 10%.
- على الشاشات الأصغر: بطاقتان في كل سطر، والرصيد بعرض كامل.

**اشتراكات المشترك:** بطاقات قابلة للضغط. السطر الأول: الاسم والرصيد. السطر الثاني: التفاصيل ورابط «الكشف». الاشتراك الحالي بحلقة برتقالية.

**فترة الكشف:** حقلا تاريخ، عرض كل منهما 180px.

**دفتر الحركات:**
- **8 أعمدة فقط:**
  1. التفاصيل (السهم)
  2. الرقم
  3. التاريخ
  4. الوصف (280 إلى 460px، يلتف)
  5. النوع (شارة الحركة)
  6. مدين (`--danger-ink`)
  7. دائن (`--success-ink`)
  8. الرصيد (وزن 800)
- **ارتفاع الصف:** 60px.
- **شرائط الأشهر:**
  - سطر لكل شهر ارتفاعه 40px، بخلفية `surface-secondary` وطرفين مستديرين.
  - فيه اسم الشهر ومجاميعه بخط صغير.
- **التفاصيل عند الطلب** لكل حركة: البنك، المستخدم، رقم الحوالة، السلسلة، وما بقي من أعمدة.
- **أنواع خاصة من الصفوف:**
  - الحركة الملغاة: نص مشطوب بشفافية 60%.
  - العكسية: خلفية خفيفة.
  - المميّزة: `accent` 7%.
  - الدفعة المقسّمة: سطر صغير بلون `--t-split-ink`.
- **قائمة إجراءات الصف:** زجاجية، وتبقى داخل الشاشة، وتُغلق بـ Escape.

**على الجوال:** كل حركة بطاقة. شريط الشهر سطر نصي. الخلية الفارغة في مدين أو دائن تختفي.

## 13. الصناديق المالية (تصميم خاص)

- **التبويبات:** مقطّعة، ومع كل تبويب عدّاده. عدّاد التبويب الفعّال بخلفية `accent-soft`. تحتها سطر شرح.
- **ثلاث بطاقات أرقام** (أعمدة متساوية، وعمود واحد على الجوال):
  - في كل بطاقة: أيقونة 48px بلون الحركة، والتسمية، والمبلغ بحجم 24px، وسطر صغير.
  - البطاقة تعمل كفلتر، والمختارة بحلقة برتقالية.
- **الفترة:** أيقونة 44px، واسم الفترة الأسبوعية، وشرحها.
- **جدول الصناديق:**
  - الصف 60px.
  - رقم الصندوق رابط بوزن 800.
  - النوع: أيقونة 34px بلون الحركة، فيها نقطة حالة (مفتوح بلون `split`، مغلق بلون `success`).
  - المبالغ بوزن 800 وتحتها التحويل بالعملة الأخرى.
  - التفاصيل عند الطلب.
  - على الجوال: زر الفعل بعرض كامل.
- **«صناديقي» (أمين الصندوق):**
  - بطاقات بعرض أدنى 280px وزوايا 20px.
  - في الرأس: رقم الصندوق ونوعه.
  - المالك: صورة 26px.
  - المبلغ 24px.
  - الذيل: الحالة وزر بعرض كامل.

### 15.1 المرجع لكل عنصر

افتح النموذج إلى جانب الموقع. لكل صفحة أو نافذة:

1. طابق الحقول والأزرار مع `specs/*.json`. هذه أُخذت من كود الموقع، وهي مصدر الحقيقة لما يجب أن يوجد.
2. طابق الشكل مع النموذج.
3. خذ القيم الدقيقة من ملفات CSS في الأرشيف.

### 15.2 التحقق في كل مرحلة

- **الاختبارات:**
  - `npm run lint`
  - `npm test`
  - `npx vitest run`
  - `php artisan test --compact` للمتأثر
  - اختبارات المتصفح `npm run test:browser`، و`test:reports`، و`test:print`، و`test:readings`
- **ملاحظة:** هذه الاختبارات الأربعة كانت تفشل قبل الترقية بالخطوة نفسها، فلا تُعتبر فشلًا جديدًا إلا إن تغيّرت الخطوة.
- **ملاحظة لبيئة السحابة:** إن طلب Playwright متصفحًا غير موجود، اربط المجلد المطلوب بالمتصفح المثبت في `/opt/pw-browsers/`. لا تشغّل `playwright install`.
- **لقطات شاشة:** لكل صفحة تغيّرت، بالثيمين وبالشكلين المصمت والزجاجي، على سطح المكتب وعلى الجوال (390px).
- **قائمة الفحص:**
  - الهافر والتركيز.
  - التباين (AA).
  - لا قصّ ولا التصاق في الحقول.
  - المحاذاة والمسافات متطابقة بين النماذج.
  - القوائم الزجاجية داخل الشاشة.
  - لا مربعات بيضاء في الداكن.
- **المطابقة الوظيفية:** نفس الحقول، ونفس أسماء الإرسال، ونفس التحقق، ونفس الصلاحيات (الأزرار التي تظهر حسب الصلاحية تبقى كذلك).

### 15.3 قائمة «لا تنسَ»

- **إضافات وتعديلات:** إضافة القواطع، والطبلونات، والفروع، والمحافظات، والمناطق، والمناطق الفرعية، والتعرفات، والمستخدمين، ونماذج الشركة، وكل صفحات التعديل.
- **الأقسام:** كل نوافذ «المشتركون» و«المالية والتحصيل» و«الإدارة».
- **الحالات:** الفراغ والتحميل والخطأ لكل جدول ونموذج.
- **التبديلات:** الثيم والفرع واللغة الرقمية للأرقام في كل مكان.
- **الصلاحيات:** ما يظهر لكل دور يبقى كما هو.
- **الأرقام:** 34 صفحة، 78 نافذة ونموذجًا، 631 حقلًا، 58 نافذة تأكيد. تأكد من وجود كل واحد منها في التصميم الجديد.
